# skeleton · 通用骨架（跨行业不变件）

> **这是干什么的**：整条流水线里**与行业无关**的部分——元 skill、四个角色文件、治理纪律。换领域时**一行都不用改**。
> 定位比喻：骨架 = 发动机；领域包（`..\domains\`）= 活塞。换领域换活塞，不换发动机。

## 包含清单

| 件 | 作用 |
|---|---|
| `skills/meta-requirement/` | 唯一元 skill：大白话 → 六件（意图卡/规格/三层验收/失败模式映射/升级包/术语表）。任何需求必经 |
| `agents/planner.md` | 规划者：拆段、选 skill、判 Gate、维护 state.json |
| `agents/builder.md` | 执行者：段内执行、只交断言证据、不自评 |
| `agents/reviewer.md` | 独立复核者：只见三输入、逐条 pass/fail、"无法判定"回人 |
| `agents/verifier.md` | 机械验证者：跑机械证据、不改代码、失败即停 |

## 三条纪律

1. **不许往骨架塞领域内容**。领域术语 → 领域包 glossary；领域事故 → 领域包 failure-modes；行业流程 → 领域包 skills。骨架文件里出现行业专名即为泄漏信号。
2. **改骨架 = 高风险动作**：先出草案 → 人审 → 过回归（用领域包 evals/score.py 跑 golden case 干测）→ 落修订记录，不过不启用。
3. **骨架按"名字"消费领域数据**：元 skill 的 inputs（glossary/failure-modes）与机械评分器（score.py）由领域包提供，路径以调用时声明的领域包为准。

## 与领域包的分工

| 关注点 | 归属 |
|---|---|
| 流程怎么走、角色怎么隔离、Gate 怎么拍 | 骨架（本目录 + 治理不变量纪律） |
| 状态机实例（段/链路/Gate 映射） | 领域包 `workflow/`（不变量规则以骨架纪律为准） |
| 术语、失败模式、golden case、基线 | 领域包 `specs/` `evals/` `baselines/` |

> 注：`evals/score.py`（评分器）随领域包走——其路径逻辑绑定包内 `cases/` 目录；若未来多域需单点维护，再参数化（域 #2 时决策）。
