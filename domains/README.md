# domains · 领域包（血肉层）

> **这是干什么的**：领域知识的家——一个领域一个文件夹。装的是：该领域的术语、失败模式、行业 skill、golden case、基线、状态机实例。
> 与骨架的关系：骨架（`..\skeleton\`）管"流程怎么走"，领域包管"这个领域什么算对"。

## 如何新建一个领域包（检查清单，按序）

1. **准入三条件自查**（证据写进新包 DOMAIN.md）：该域任务重复出现？结果可机械核验？有历史答案或能现冻 golden case？——三条件缺一，不建包。
2. **建文件夹** `domains/<域短名>/`，写 `DOMAIN.md`（这个包是干什么的、准入证据、包含清单、当前状态）。
3. **specs/**：glossary.yaml（该域术语，从真实材料挖掘）+ failure-modes.md（该域失败模式，从事故/历史问题推导，FM-xx 编号、五栏、唯一属主）。
4. **skills/**：行业 skill 从失败模式逐条推导，**数量由失败模式数量决定**，不由阶段数量决定。
5. **evals/**：golden case（input/context/decisions/expected/check.py 五件，断言编号 AS-n）+ score.py（从示例包复制，评分器路径逻辑绑定包内 cases/）。
6. **workflow/**：状态机实例（段/Gate 映射 + 链路启用决策）；治理不变量（G1–G3、重试、预算、仲裁、回退重签、覆盖审计）以骨架纪律为单一事实源，不在实例里复制第二份。
7. **baselines/**：第 0 周人工计时落这里。
8. **escalations/**：从示例包复制升级包样例（脱敏，E-/EP- 各一份），保留格式示意。

## 通用失败模式的归属约定

failure-modes.md 里 **FM-Bxx（Agent 执行层）本质是跨域通用模式**，暂随首次发现它的领域包存放。**域 #2 建包时**，把通用条目晋升到骨架层共享库（届时一并参数化 score.py）——现在不预做，避免空转抽象。
