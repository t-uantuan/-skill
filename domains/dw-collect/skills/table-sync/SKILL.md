# 表同步执行（试点链路 1）

> 占位符〈元数据表〉〈对账脚本〉〈同步脚本套件〉〈断点控制表〉〈入仓脚本〉等以本包 specs/glossary.yaml 的实际词条为准。

## 步骤（每步可判定完成）

1. **写元数据**：向 `〈业务库〉.〈元数据表〉` 插入一行（同步类型/检查列/分片列/并发）。
   → 回读该行确认写入成功（杀 FM-A01：静默失败）。
2. **写脚本参数**：复用 `〈同步脚本套件〉`，只加参数不改脚本本体。
   → 约束：远程 SQL 禁止反引号嵌双引号（杀 FM-A01/FM-A09）；>2min 命令 nohup 后台化（杀 FM-A10）。
3. **首跑**：全量表直接跑；增量表先 `--init` 首日全量。
   → 断言：控制表断点值非空（杀 FM-A02）。
4. **对账**：`〈对账脚本〉` 跑本表。
   → 断言：源库 vs 落盘行数 diff=0；append 表 0 行属正常不算异常（杀误报疲劳）。
5. **幂等验证**：同分区重跑一次。
   → 断言：重跑前后 count 相等（杀 FM-A03——幂等事故真实踩过的坑）。
6. **入 ODS**：`〈入仓脚本〉` 挂分区。
   → 断言：ODS count 与落盘一致；验收查询限时 30s（杀 FM-A07）。
7. **汇报**：只报断言结果表，不写"应该没问题"。

## 禁止

- 不改既有脚本本体（新需求=新参数行）
- 不跳过幂等验证（它杀的是真实发生过的事故）
- 不用"基本完成/应该可以"结案——只用断言结果
