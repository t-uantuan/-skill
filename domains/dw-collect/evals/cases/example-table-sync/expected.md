# example-table-sync · 预期结果（模板）

## 预期交付物

一次成功的〈表X〉增量同步交付 = 六步断言（table-sync skill 第 1–6 步）全部有证据 + 交付单。

## check.py 全绿判据（复跑判定标准）

| 断言 | 判据 |
|---|---|
| AS-1 对账 diff=0 | 源库 `〈业务库〉.〈表X〉` 行数 = 落盘当日分区行数 |
| AS-2 幂等重跑 count 不变 | 同分区重跑前后落盘行数相等（`--quick` 跳过本项；quick 模式其余全过也只标"不作正式全绿"，正式验收与回归必须全量跑） |
| AS-3 断点值非空 | `〈断点控制表〉.断点值` 非空 |
| AS-4 ODS=落盘（且查询<30s） | `〈ODS库〉.〈表X〉_inc` 当日分区 count = 落盘 count |

- 全部 PASS → check.py 退出码 0（score.py 标 GREEN）
- 任一 FAIL → 退出码 1
- 环境不可达 / 业务库不可查 → 退出码 2（SKIPPED，不算绿也不算红——环境未验证）

## 语义层与人判层（本 case 冻结的历史裁决）

- 语义：同步类型=增量 lastmodified、检查列=〈检查列A〉、幂等=临时目录+原子 mv、断点=写入后回读（依据见 decisions.md 拍板表）
- 人判：补历史不出岔子 = 幂等断言必过；对一下数 = AS-1/AS-4
